# ROMtool — In-Building RF ROM Estimator (v0.8.0: LTE + public safety + 5G NR + Class 1 labor estimates + governance + commercial wrap + sanity gates + actuals loop + RF link + AI endpoints + the 60k-seat stadium morning package)

Rough-order-of-magnitude estimator for in-building wireless (DAS): coverage
prediction, antenna count and a parts-only BOM, driven through a local REST API
plus a minimal canvas UI. Headless RF core is pure Python (stdlib only), so the
whole tool runs offline after install. Owner: Matt Busdiecker. Spec lives in
`SPEC.md` — locked product decisions are in there.

## Stack

- Python 3 venv + FastAPI + SQLite (one file; each project stored as one JSON
  model blob, floor images embedded as base64 PNG/JPEG in the same store)
- Static vanilla-JS canvas UI served by the same app (no build step)
- Pure-Python RF engine (`romtool/` package: physics, geometry, cascade,
  predict, BOM, PNG report) — no numpy, no image libs
- Class 1 estimate engine (`romtool/estimate.py`) + zero-dependency XLSX
  writer (`romtool/xlsx.py`), data-driven from `config/labor_units.json`
  (regenerated by `scripts/build_labor_units.py`) and `config/estimating.json`

python3 -m venv .venv

cd /root/assistant/romtool && .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8807

first boot: 2 floors, 12 m x 9.2 m plate at 10 px/m, off-air source ->
repeater -> 7/8 in trunk -> two 2-way splitters -> 4 omni antennas (2/floor),

## Phase 4: Class 1 labor estimate engine

The estimator (romtool/estimate.py) carries a full estimate down the labor
stack with every line visible in the recap:

- **Labor-unit catalog store**: `config/labor_units.json` — 134 rows across
  zones A-Rooftop, B-Headend, C-Closet, D-Pathway, E-Cellular-passive,
  F-FTTE-active, G-ERCES, H-Testing, I-Eng-PM, J-Electrical, K-Access-ADDERS,
  L-Finishing/Paint, M-Downtime/Logistics, N-Wrap and the new
  O-DC-Power-Plant. Regenerated from the owner's research CSV with
  `.venv/bin/python scripts/build_labor_units.py` (never hand-edit the JSON;
  a test asserts the store matches regeneration). Row kinds: `minutes`
  (takeoff lines), `factor` (11 multiplier rows — never line quantities),
  `quote` (0-minute DAY/LOT cost carries).
- **Estimate definition** (POST /estimates): `locations[]` each with id/name,
  `lines[{catalog_id, qty}]`, access method `ground|ladder|lift|scissor|rope`,
  condition flags `occupied|exterior|constrained_access`, optional
  `power_plant` auto-sizing block, plus `schedule` night/weekend flags,
  `travel_moves[]` (M05), `downtime_windows[]` (M01 blacked-out idle days),
  `crew` plan and optional `rate_overrides`.
- **Factor stack per line** (visible in recap JSON, CSV and XLSX): base
  minutes (qty × unit minutes low/mid/high) → condition factor (M03/M04/M07)
  → access factor (K03/K05/K06) → schedule premium (M02) → supervision
  adders (N01 foreman at the 0.5 productive haircut + N02 super 8-15%) →
  wrap. K-Access-ADDERS minute rows never take the access factor (they are
  the access adders). Derived estimate-level wrap lines (M05 travel, N03
  orientation, N04 cleanup per crew-day) carry base minutes unstaked.
- **Crew + schedule math**: crew-days = ceil(direct hours / (crews × (techs
  + foremen) × hours/day)); crew-weeks on the 5-day week; M01 lockout days
  carry idle crew-day cost at the blended rate, not hours.
- **Power-plant helper (optional)**: per-location
  `{runtime_hours, load_amps, ...}` auto-derives O01 + rectifiers (N+1 =
  ceil(load/50 A) + 1) + battery strings (Ah = runtime × load, strings =
  ceil(Ah / 120 Ah), IFC 510.4.2.3 12-hr minimum with a recap warning below
  it). Supersedes B05/B06 at detail level.
- **$ rollup in config** (`config/estimating.json`, editable defaults):
  burdened tech $85/h + foreman $105/h rate card, I05 PM 10%, OH 10%,
  profit 10%, N05 line-risk contingency by catalog source quality
  (P 3% / E 7% / G 10%) — contingency on labor dollars only.
- **Endpoints**: `POST /estimates` (compute + store),
  `POST /estimates/compute` (dry run), `GET /estimates`,
  `GET/DELETE /estimates/{id}`, `GET /exports/estimates/{id}/recap.csv`,
  `GET /exports/estimates/{id}/recap.xlsx` (zero-dep writer). Estimates are
  stored in SQLite alongside projects (definition + recap JSON blobs).
- **Tests**: worked multi-location stadium scenario (rope roof, lift bowl
  with antenna shrouds, occupied+constrained closet, ERCES headend with HVAC
  + the DC plant, night differential, travel moves, lockout day) asserted
  against hand math on ~25 lines including factor-stack order, K-zone rule,
  wrap/crew-day math, the $ chain, power-plant string counts, API CRUD smoke
  and export smoke; engine+exports benchmark well under 5 s.

## Phase 3: 5G NR

- **5G NR band presets**: `N71_600` (600 MHz, DL 617–652 → center 634.5 MHz),
  `N41_2500` (2.5 GHz TDD, 2496–2690 → center 2593 MHz), `N77_CBAND`
  (US C-band 3.7–3.98 GHz DL → center 3840 MHz). NR bands carry
  `technology: "5G NR"`; the P.1238 validity window in config was widened to
  300–6000 MHz so the C-band preset is in-model (P.1238 ed. 10+ is derived up
  to 100 GHz; VHF 150 still warns as before). Cable loss tables gained 3.0/4.0
  GHz anchors so n41/n77 cascade runs interpolate instead of clamping at the
  2 GHz anchor (representative values — edit per cable datasheet).
- **n78 (3.3 GHz) is a config option, not a preset**: copy an `N77_CBAND`
  entry in `config/default.json` (or a project `config_overrides.bands`
  list) and set `id`/`label`/`freq_mhz` — e.g. a 3.3–3.4 GHz block at 3350 MHz
  or the EU 3300–3800 midpoint 3550 MHz:
  ```json
  { "id": "N78_3300", "label": "5G NR n78 (3.3 GHz, 3300-3400)",
    "freq_mhz": 3350.0, "ambient_dbm": -85.0, "technology": "5G NR" }
  ```
  Everything downstream (solve, predict, SS-RSRP, composite) is band-agnostic,
  so no code changes are needed.
- **NR SS-RSRP KPI preset**: `kpi_presets.nr_ssrsp` thresholds apply to every
  band whose `technology` matches the preset's (default "5G NR"). The design
  KPI is SS-RSRP ≥ threshold (default −95 dBm) over ≥ min area % (default 95%),
  whole floor; plus a `rsrp_class_pct` area summary from the editable class
  table (excellent ≥ −80 / good ≥ −90 / fair ≥ −100 / edge ≥ −110, `none`
  below). These buckets are editable planning defaults, not normative 3GPP
  classes. Optional per-band `ss_rsrp_offset_db` converts the composite
  carrier RSSI to an SS-RSRP estimate (≈ total power − 10log10(#RE) of the
  carrier) — set it per band when you care about per-RE levels; leave unset
  for a 0 offset. The single-tier/NFPA presets stay on the composite RSSI.
- **Multi-band composite / best-band view**:
  `GET/POST /projects/{id}/floors/{fid}/composite?bands=N71_600,N41_2500,N77_CBAND&step=…`
  runs the per-band prediction on the same pixel grid for each selected band
  and returns, per grid point, the strongest band's level (`values_dbm`),
  which band serves it (`best_band`) and which antenna (`best_server`), plus
  per-band KPIs (`per_band`, each with its full presets incl. SS-RSRP) and a
  `union_kpi` (OR-coverage: % of points where any selected band meets that
  band's own single-tier threshold). **Semantics:** different NR carriers do
  not combine into one signal — the composite answer is "best coverage
  available at this point, from which band and which antenna", never a linear
  RF sum. Selection is comma-separated band ids (deduped, order preserved);
  duplicates/whitespace are tolerated. Also rendered as
  `/composite.png` (heatmap + union badge).

## Phase 2: public safety

- **Legacy LMR bands**: `VHF_150` (154 MHz, P25/FM), `UHF_450` (453 MHz),
  `PS700` (772 MHz, 700 MHz public-safety narrowband, base TX 769–775),
  `PS800` (860 MHz, 800 MHz PS, base TX 851–869). **FirstNet Band 14 LTE**:
  `B14_FIRSTNET` (763 MHz DL center, 758–768 DL). Frequencies/ambients are
  editable config entries (the -85 dBm ambient default is a phase-1 baseline
  you will want to override per site).
- **P25/FM sources**: source elements take a `subtype`:
  `off_air` (default donor model) or `direct` — a base-station/direct-inject
  feed that puts a configured `injection_dbm` (default +5 dBm, editable in
  config and per element) on the port instead of the ambient+donor budget.
  Unknown subtypes are rejected at create/solve.
- **Low-band config overrides** (P.1238 validity): ITU-R P.1238 is derived for
  ~300 MHz–3 GHz (`itu_p1238_valid_mhz`, editable). Predicting a band below
  that window (VHF 150 does) is extrapolation: `predict` returns the estimate
  plus a `model_warnings[]` entry, and every band accepts
  - `n_exponent_overrides: {"office": 34.0, ...}` — per-environment N for the
    band (VHF ships with higher-N defaults),
  - `wall_loss_scale_db` — additive dB correction on every P.2040-scaled wall
    loss (VHF/UHF ship with small positive corrections).
  At 154 MHz cable loss clamps to the 0.7 GHz anchor (conservative; below-0.7
  band sweeps are not part of the ROM model).
- **NFPA two-tier KPI with critical-area polygons** (phase-1 deviation, now
  done): draw polygons on a floor (UI "Critical area" tool or REST), and tier 2
  of the NFPA preset evaluates inside the polygon union — per polygon and
  combined (default 99% min area, AHJ-editable in `kpi_presets.nfpa_two_tier`;
  a tier's default scope, whole-floor vs critical-areas, can be forced with a
  `scope` field). Tier 1 is always whole-floor; a floor without polygons falls
  back to whole-floor tier 2 with a note. Reports: per-band
  `/nfpa_report(.json|.png)` endpoints and a live NFPA panel in the UI.

## Editing the physics/config

Everything numeric lives in `config/default.json` (or a file pointed at by
`ROMTOOL_CONFIG`), and each project can layer `config_overrides` on top.
The estimate engine has its own data files: `config/estimating.json`
(factor midpoints per row, access-method map, rate card, PM/OH/profit,
contingency bands by quality, power-plant sizing, crew defaults) and
`config/labor_units.json` (the catalog — regenerate from
`/root/assistant/research/das-build-unit-catalog-v2.csv` with
`scripts/build_labor_units.py`; per-estimate `rate_overrides` deep-merge on
top of the rate card):

- Bands: LTE (B12/B13, B5, B2, B66), FirstNet B14, LMR (VHF 150, UHF 450,
  700/800 PS), 5G NR (n71 600, n41 2500, n77 C-band — plus any added band
  such as n78 3.3 GHz) — DL center MHz, ambient, `technology` for NR opt-in,
  and optional per-band `n_exponent_overrides` / `wall_loss_scale_db` /
  `ss_rsrp_offset_db`
- Environments (ITU-R P.1238 N: office 30 / commercial 22 / residential 28),
  plus P.1238 validity window
- Floor loss dB/floor (default 15.4), wall-loss reference frequency (2 GHz)
- Wall materials with dB @2 GHz (concrete 15, CMU 10, drywall 4, glass 5,
  low-E glass 8, wood 4, metal 30) — frequency-scaled linearly in the
  log-frequency domain per the P.2040-curve rule
- Cables: dB/100m anchors, interpolated linearly in log-frequency
- Splitters 2/3/4-way, taps, couplers, antennas, repeater gain/max-out/ports,
  source subtypes incl. direct-inject level
- KPI presets: single tier (-95 dBm @ 95% area), NFPA two-tier
  (tier 1 -95 dBm @ 95% general, tier 2 -95 dBm @ 99% critical) with per-tier
  `scope` override, and the NR SS-RSRP preset (technology-matched bands)
- Report color scale + critical-area drawing colors

The engine is band-agnostic: more NR bands (n78 3.3 GHz, mmWave later) are
additive entries in this file — see the Phase 3 section for the n78 snippet.

## Modeling notes (read before trusting numbers)

- Path loss: `PL = 20log10(f_MHz) + N·log10(d_m) + Lf·n_floors − 28` (P.1238)
  — applied 300 MHz–6 GHz (config window; covers the NR C-band preset, which
  sits above the historical 3 GHz note but inside P.1238 ed. 10+ scope).
  VHF 150 is still extrapolation: treat outputs as relative only, and use the
  per-band overrides to calibrate against a data-derived N.
- Wall crossings: strict ray/wall-segment intersections of the straight
  antenna→point line, same floor only; inter-floor antennas use the floor-loss
  term instead (the slab dominates).
- Composite signal = linear (mW) sum over all solved antennas; best server =
  per-point max. Whole-floor KPI is over the full floor canvas rectangle;
  critical-area KPI over grid points inside the polygon union (grid-point
  membership, not sub-cell area weighting).
- Donor budget: ambient + donor antenna gain − optional inline feeder loss +
  the physical feeder cable run (source→repeater) so it lands in the BOM;
  `direct` sources replace the ambient term with a fixed injection level.
- Port powers are per-band, single-carrier DL estimates (no multi-carrier
  power sharing yet); antennas cap port power at their max-port setting.
- SS-RSRP vs RSSI: per-band predict returns composite carrier RSSI; the NR
  preset treats that as SS-RSRP except for an optional per-band
  `ss_rsrp_offset_db` (per-RE conversion). For ROM purposes the design
  thresholds absorb the difference when the offset is unset.
- Multi-band composite = per-point best band (max), not an RF sum; union KPI
  is an OR over per-band thresholds.
- Known simplifications vs real propagation: no ray tracing (per SPEC), no
  capacity/Monte Carlo, relative accuracy only.

## Phase 5 (E2): estimate governance + procurement layer (v0.5.0)

`romtool/governance.py` + four new store tables make estimates first-class
versioned objects with full commercial governance. Every rule is
config-driven (`config/governance.json`), nothing hard-coded:

- **Versioned estimates**: every create/`PATCH` freezes an immutable
  revision snapshot with a diff summary (lines added/removed/re-priced by
  stable `line_id`s, definition meta changes, totals drift). `GET
  /estimates/{id}/revisions[/n]`. Revisions only while `draft`/`review`;
  approved/sent/superseded estimates are frozen (409).
- **Full audit log**: `GET /estimates/{id}/audit` — actor (X-Romtool-Actor
  header, `?actor=` or config default), action, UTC timestamp, revision and
  exact changed paths, for estimate writes, register edits and quote actions.
- **State machine**: `draft → review → approved → sent → superseded`
  (side-steps: review→draft reject, approved→superseded withdraw). Illegal
  transitions are HTTP 409 with the allowed list; delete is blocked from
  approved/sent. State + revision are stamped into recap.csv/recap.xlsx.
- **Assumption register**: every E-quality labor-norm line auto-populates a
  row (catalog id, line key, text = item + reference, owner default
  "Senior Project Estimator", review date, status). Close-out ladder
  open → verified → closed with 409 on skipped steps; verified rows survive
  line removal as close-out evidence. Export:
  `/exports/estimates/{id}/assumptions.csv`. The stadium fixture validates
  exactly 24 auto rows (18 definition + 3 wrap + 3 power-plant lines).
- **Quote register**: vendor quotes with scope, amount, currency,
  `binding_until` (inclusive — binding through the date, expired strictly
  after), inclusions/exclusions, linked estimate line ids and a
  draft → received → bound → expired workflow (expired → received re-issue).
  Every expired quote warns exactly once in the governance view and the
  recap exports.
- **Bid-tab comparison**: `/estimates/{id}/bid_tab` — quotes grouped by
  linked lines (or whole-estimate), ascending rank, low/median/high over
  active received/bound quotes, gap analysis vs the estimate carry (wrapped
  labor + line-risk contingency + idle-cost carry; whole-estimate vs grand
  total), carry-vs-lowest/highest notes.
- **Inclusions/exclusions sheet**: `config/commercial_draft.json` templates
  + definition-derived lines (night/weekend premiums, travel, blackout
  carry, supervision, power plant) + verbatim vendor-quote terms, exported
  exported as zero-dependency `/exports/estimates/{id}/inclusions_exclusions.xlsx`
  (2 sheets) and `.pdf` (new zero-dep `romtool/pdf.py` writer).

## Phase E3 (v0.6.0): commercial wrap depth

`romtool/commercial.py` + `romtool/bidform.py` + one new store table
(`estimate_scenarios`) put the full commercial wrap into the recap $ chain
and the bid package. Every constant lives in the new editable
`config/commercial.json`; the wrap order is documented in the config
comment, in `estimate.py`'s docstring and on `/how-it-works` §11:

- **Documented $ chain** (money lines appear in exactly this order, and
  every estimate carries `recap.commercial` with the applied values):
  direct labor + supervision → downtime idle carry (M01) → small-tools/
  consumables allowance (3% × labor+downtime) → escalation → sales/use tax
  → insurance/bond carry (1.5%) → PM → overhead → profit (risk tiers low 8
  / standard 10 / high 12) → line-risk contingency (unchanged P3/E7/G10).
  Stadium mid-band hand chain: labor $51,680.55 + downtime $3,560.00 →
  small tools $1,657.22 → escalation $0 (no anchor) → taxes $0 (all-labor
  exempt default) → insurance $853.47 → PM $5,775.12 → OH $6,352.64 →
  profit $6,987.90 → subtotal $76,866.88 + contingency $3,661.44 =
  **$80,528.33**.
- **Escalation indices** (labor 3.5%/yr, copper 8%, equipment 4% as
  assumption-grade practice defaults, each with `base_date`): factor =
  1 + days(base_date → anchor)/365 × rate%, simple interest, calendar days,
  never de-escalating. Anchor = definition
  `commercial.escalation.anchor_date`, else the midpoint working day of the
  with-crews schedule (definition `start_date`), else skipped with a
  warning. `commercial.escalation.index` picks labor/copper/equipment.
- **Sales/use tax rules**: zone-prefix → line-type classification (editable
  map), taxable vs exempt types, 7% editable jurisdiction rate (override
  per estimate via `commercial.tax.rate_pct`). Shipped default: every zone
  is labor and labor is exempt — the taxable base and the tax are $0.00 and
  reported explicitly. Classify a zone `equipment`/`materials` only when
  your jurisdiction actually taxes that base.
- **Crew-loading schedule** (`GET /estimates/{id}/schedule`): per-location
  crew-days = ceil(location wrapped mid hours / per-crew daily capacity);
  working-day calendar = first `days_per_week` weekdays from Monday;
  `downtime_windows` with a `start` date blackout those calendar days
  (undated windows keep pricing M01 but block nothing); phases claimed
  whole by a free crew in definition order; early bound = all configured
  crews, late bound = single-crew serial; weekly hours above the 40 h
  double-time threshold are flagged with the DT multiplier (schedule-level
  information — the M02 differentials remain the costing mechanism).
- **Cash-flow phasing** (`GET /estimates/{id}/cashflow` +
  `/exports/estimates/{id}/cashflow.csv|.xlsx`): milestone splits from the
  contract config (NTP 10 / DESIGN 15 / INSTALL 60 / COMMISSION 10 /
  CLOSEOUT 5, validated to sum to 100) shape the monthly curve of the
  wrapped grand total (mid); INSTALL spans the calendar months the early
  schedule covers (or ceil(work days / 21) without dates); months are
  labeled from the start date or M0..Mn indices.
- **What-if scenarios** (`POST /estimates/{id}/scenarios`,
  `GET .../scenarios`, `GET .../scenarios/{sid}/diff`): stored overlays of
  `access_overrides` / `factor_overrides` / `qty_overrides` /
  `quote_swap` recomputed against the current base at diff time (never
  stale). Diffs are line-level (only qty / hours mid / labor mid moved)
  plus totals deltas that include the wrap amplification. Quote swaps
  replace the named lines' wrapped labor with the quote amount allocated
  proportionally by each line's share per band and flow through the full
  wrap chain; hours/schedule stay engine-side.
- **Bid form** (`/exports/estimates/{id}/bid_form.pdf|.xlsx`): base bid,
  `alternates[]` priced by the identical engine (locations-only = whole
  current scope incl. auto-derived power plant; lines specs = subset, new
  lines need explicit qty and drop the power_plant block to avoid
  double-carrying O-zone derived lines; `kind: deduct` signs the credit
  negative), unit prices = wrapped total / definition `antenna_points`
  (scalar or per-location map), condensed schedule of values in wrap order,
  exclusions summary from the commercial-draft sheet, signature block.

## Phase E4 (v0.7.0): intelligence, RF link, actuals loop

Four new modules + six new config files; nothing numeric left code-side:

- **Sanity gates** (`romtool/sanity.py`, `config/sanity.json`,
  `config/checklists.json`): `GET /estimates/{id}/sanity` runs six gates over
  the stored recap + definition + quotes — labor-share windows per venue
  archetype (six shipped: stadium/hospital/warehouse/tunnel/hotel/office;
  zone-letter bands), hours→crew-days/weeks ceil consistency, E-density

## Building-type default loss and automatic antenna placement

**Building-type default loss.** Set `building_type` on a project or floor
(floor wins; `POST/PATCH /projects`, `POST/PATCH .../floors`). Allowed ids are
the keys of `building_types` in `config/default.json`: office, office_open,
office_standard, office_dense, hospital, warehouse_open, school_campus,
hotel_residential, parking_garage, stadium_venue, retail_mall. When a floor has no walls drawn, predict and
autoplace use that type's N and optional `clutter_db_per_m`:
`PL = 20log10(f) + N*log10(d) + clutter*d - 28`. With walls drawn, or no
building type, behavior is unchanged (environment N plus wall crossings).
Every value carries a grade and reference. Grade P is published: office 30,
hotel_residential 28, retail_mall 22 (ITU-R P.1238 Table 2, 1.8-2 GHz column,
the same numbers as `environments`; re-check against the edition you cite).
Grade E is an estimate with no published coefficient, set to an analog and
flagged for calibration: hospital 30 and school_campus 30 (office analog),
warehouse_open, parking_garage and stadium_venue 22 (commercial analog).
`clutter_db_per_m` is calibrated (grade C) for office, hotel_residential,
hospital and warehouse_open; the other types are 0.0 or grade E estimates. A
band can override N per building type with `n_exponent_overrides.<building_type>`.
`predict` returns `loss_model` showing which source applied.

**Office subtypes.** `office` stays the generic type and the fallback when the
layout is unknown. Pick a subtype that matches the layout: `office_open` for
open plan (atria, halls, open furniture; clutter 0.1 dB/m, grade E),
`office_standard` for a standard corporate layout (0.3 dB/m, the calibrated
office value, grade C), and `office_dense` for dense private offices, cubes or
labs (0.6 dB/m, grade E). All three use the office N (30, grade P). The open and
dense clutter values are starting points taken from the `clutter_map` classes
and are not calibrated.

**System type.** `system_type` is one of `das`, `dran` or `bda` (the list is
`system_types` in config). Set it on the project, on a floor (the floor wins
over the project) or in the autoplace request (the request wins over both).
When the building type has a `clutter_by_system` value for that system, the
loss model uses it in place of `clutter_db_per_m` and reports
`clutter_source: building_type_system`. Otherwise the building type's own
clutter applies. No building type has `clutter_by_system` values yet, so the
setting changes nothing until calibration adds them. An unknown system type
returns 422 from the project, floor and autoplace endpoints.

**Autoplace.** `POST /projects/{pid}/floors/{fid}/autoplace` with
`bands` (required), `antenna_id`, `threshold_dbm` and `coverage_target_pct`
(default the single-tier preset, -95 dBm / 95%), `rsrp_offset_db`, `nfpa`
(auto: bands in `autoplace.public_safety_band_ids` use the NFPA two-tier
rule), `step_px`, `max_antennas`, `source` / `repeater` overrides,
`headend {x_px,y_px}`, `feed_element_id`, `outline` (also `floor.outline`),
`verify_max_points`, `dry_run`. It replaces earlier auto-placed elements
(flag `auto: true`) on that floor, builds source, repeater, a spatially
clustered splitter tree and cable runs, and saves them, so `/cascade/solve`,
`/predict` and `/bom` work unchanged. Response: antenna count, achieved
coverage per band and tier, iterations, per-antenna EIRP, cascade port-power
minimums, warnings, runtime and the BOM.

Algorithm: hex-lattice seed sized from the link budget, greedy fill (add the
candidate that newly covers the most uncovered points), prune (remove
antennas while every requirement holds). An outer loop solves the real
cascade and re-plans until the solved EIRPs meet the target; the final layout
is verified with the same arithmetic as predict. Deterministic, no randomness.
Stops when the target is met, at `max_antennas`, when fill stalls, or with a
422 if the link budget supports under 2 m radius.

Limits:
- Thresholds are in the predict domain (composite carrier power). For an LTE
  RSRP target pass `rsrp_offset_db` (RSRP minus carrier power, about -31 dB
  for 20 MHz).
- The default N values are generic; no-wall coverage radii are long and the
  count is only as good as the calibration against closed jobs.
- A floor with walls and no outline is placed inside the walls' bounding box,
  inset 0.5 m. Floors without walls keep the canvas rectangle. An outline on the
  request or the floor overrides both.
- Planning runs on at most 6000 points; verification on at most
  `verify_max_points` (100,000) and is coarsened beyond that (reported).
  Predict's own KPI stays canvas-wide, so `outline` only affects autoplace.
- One head-end per call. Use `feed_element_id` to hang a floor off an existing
  repeater/splitter port; otherwise each floor gets its own source and repeater.
- Drawn walls make it much slower (ray tests per point and antenna).
- Cable lengths are Manhattan distance plus 3 m per run (grade E); each run stores its L-shaped route (see the extensions section). Port
  power below 0 dBm is reported, not fixed (no second head-end or sectors).
- Measured on a 960 x 960 px plate at 10 px/m (9,216 m2, about 99,000 sq ft),
  two bands, 27 antennas: 1.6 s with default verification; 18 s with
  `verify_max_points=0` at step 1 (921,600 points). Plain predict on that
  floor takes about 29 s per band at step 1.

## Autoplace extensions: remotes, taps, branch losses, routes, clutter map

Each feature is a request option on `POST /projects/{pid}/floors/{fid}/autoplace`
and is off unless asked for, except route geometry, which is always written.
A request that sets none of them returns the same layout and numbers as before.
Every new numeric default carries a grade in `config/default.json` (E = estimate,
no published figure; C = company calibrated; G = guide; P = published). None of
the new values is graded P or G.

**Remote units** (`remotes: true`, a count, or `{count, max_count,
max_dl_out_dbm, max_dl_out_dbm_per_band, dl_gain_db, fiber_cable_id}`).
Instead of one repeater feeding the whole floor, the floor is split into zones.
Each zone has a remote unit (new element type `remote`, config `remote`)
placed at the load centre of its antennas (centroid, or the nearest antenna
when an outline excludes it) and its own splitter tree. Zones come from the
recursive bisection already used for splitter clustering. One head-end (source
plus repeater, at the corner rule or `headend {x_px, y_px}`) feeds each remote
over a `fiber_sm` run with an L-shaped route; fiber loss is not in the RF
cascade (the loss anchors are 0). A remote outputs `min(in + dl_gain_db,
max_dl_out_dbm)` per band, like the repeater; `max_dl_out_dbm_per_band` sets a
cap per band. The count is the smallest whose antenna ports all meet
`min_antenna_port_dbm` on every band, searched from 1 to `max_remotes`
(config, 16). A fixed `count` skips the search. When no count closes, the
count with the best worst port (smallest within 0.25 dB) is kept and a warning
says so. The response has `remotes` (count, locations in px and m, antennas per
remote, fiber length per remote and total, output per band, `budget_closed`).
The BOM lists remotes and fiber footage with fiber connectors. New values (all
E): `remote.dl_gain_db` 0, `remote.max_dl_out_dbm` 30, `remote.ports` 1,
`autoplace.max_remotes` 16. Limits: head-end port power is passed to every
remote unchanged (no optical split or fiber loss), bands are capped
independently, the remote count cannot be combined with `feed_element_id`, and
rflink labor drafts do not price remotes or fiber.

**Taps and couplers** (`taps: true` or `{min_gain_db}`). The tree may use the tap
and coupler parts in config `parts` (selected by `part_id` in the cascade and
BOM). A small dynamic program over the antenna count compares, per tree, the
equal-splitter tree the builder makes today with a stage where a coupler's
coupled port feeds a few antennas and its through port passes most of the power
to the rest (a trunk tapping off antennas as it runs). The tap stage is used
only when it lowers the worst per-antenna device loss by `tap_min_gain_db`
(config, 0.5 dB, E) or ties it and lowers the spread by that much; otherwise
the equal tree is kept. The antenna tapped first is the one nearest the feed,
so the trunk runs past antennas in order. Selection uses device losses only;
cable loss is added by the cascade. The response reports splitter, tapper and
coupler counts (`elements_added`), parts used, and the device worst loss and
spread against equal splitters (`taps`). With the shipped parts (10 dB coupler,
12 dB tap) taps start to win around 10 antennas per tree: for 10 antennas the
worst device loss drops from 13.0 to 11.6 dB. Limits: two part values only,
the choice ignores cable length and geometry, and a through-fed antenna gets a
hotter port (capped at the antenna maximum).

**Branch losses** (`branch_losses: true` or `{connectors, jumpers, diplexers,
connector_loss_db, jumper_loss_db, diplexer_loss_db}`). Fixed loss between the
end of the last run and the antenna port, from config `branch_hardware`:
connector 0.1 dB x 2, jumper 0.3 dB x 1, diplexer 0.5 dB x 1 when more than one
band shares the antenna (all E, none sourced). The sum is written on each auto
antenna as `branch_loss_db`; the cascade subtracts it before the port cap, shows
it in the node and antenna rows (`branch_loss_db`, `port_uncapped_dbm`), and the
below-0-dBm check and `cascade.min_antenna_port_dbm` use the port after it. The
BOM adds connectors, jumpers and diplexers. Limit: one allowance for every
antenna; it is not frequency dependent.

**Route geometry** (always on). Each auto run stores `route`, a list of [x, y]
px points: one L-shaped path with one bend, the first leg along the floor's
long axis (`routing.trunk_axis` in the response), so runs that share a trunk
direction overlap. `length_m` is the sum of the segment lengths over `ppm`
plus `slack_m_per_run`, so drawing and length agree. Lengths are the same as
the earlier Manhattan rule. The co-located donor feeder has no route.

**Clutter map** (`romtool/clutter_map.py`). `POST
/projects/{pid}/floors/{fid}/clutter-map` takes a plan image (multipart `file`;
without one, the floor's own image) at the floor's scale (`ppm`), lays a square
grid (`cell_m`, default 3 m), scores each square and stores `floor.clutter_map`.
`GET` returns it, `PATCH` sets or clears manual overrides (`{"set": [{"row",
"col"} or {"x_m","y_m"} or {"rect_m": [x0,y0,x1,y1]}, "class": id or "auto"],
"clear": [...], "clear_all": true}`), `DELETE` removes it. A rebuild keeps
overrides when the grid is unchanged. Scoring: dark pixels (gray below 128);
only straight runs of at least 0.9 m count as wall, which drops text and
diagonal hatching; wall crossings per metre (each wall run on a scan line is one
crossing, so thickness does not matter), averaged over both axes and a 3 x 3
window of squares; classes by threshold: exterior (empty squares reaching the
grid edge, or outside `floor.outline`), core (55 percent ink or more), dense
rooms (0.20 crossings per metre or more), light office (0.05 or more), open.
Class dB/m, all grade E and derived from the calibrated building types: open 0.1
(a third of office), light office 0.3 (office, C), dense rooms 0.6 (hospital,
C), core 1.0 (warehouse_open, the highest calibrated value), exterior 0. They are
starting values and are not calibrated per class. Thresholds are tuning values
set on synthetic plans (grade E).

With a map and no walls drawn, predict and autoplace replace the uniform
building-type clutter term by the sum over squares of dB/m times the length of
the straight antenna-to-point line inside each square. The building type (or
environment) still sets N. Walls drawn win as before and the map is then
ignored (`loss_model.source` says which applied). Without a map nothing changes.
Both call the same `ClutterField`: exact grid traversal at the square corners,
then `base x distance + bilinear residual` in between, where base is the dB/m of
the antenna's own square (a uniform map is exact). Measured error against exact
traversal on a banded plan: mean 0.1 dB, max about 1.7 dB within 30 m of the
antenna. Placement uses the map mean for the seed lattice, so dense areas are
filled by the greedy step.

Image support: PNG is decoded with the standard library only (gray, gray+alpha,
RGB, RGBA, palette, 1 to 16 bit, not interlaced). JPEG needs Pillow and PDF needs
PyMuPDF, both imported only inside the clutter module; without them a 422 says
what to install (`uv run --with pillow --with pymupdf ...`). A PDF page is
rendered at the floor's pixel width. Limits: up to about 8 megapixels (the
decoder is pure Python), hatched or open-outline cores need manual override,
hatching drawn as long straight lines scores as walls, and the plan must be
the same extent as the floor canvas (a mismatch in aspect ratio is warned).

Measured on a 960 x 960 px plate at 10 px/m (9,216 m2, about 99,000 sq ft),
bands B2_1900 and B12_700, threshold -72 dBm (composite domain), step 4: 37
antennas in 3.4 s plain; 12.3 s with a clutter map (33 antennas, map build 0.1
s); remotes with taps and branch losses 3.1 s. Verification at step 1 on that
floor still takes tens of seconds (`verify_max_points=0`).

## Drawings: one-line diagram and floor layout

Four endpoints export the drawings as SVG or PNG. The SVG and PNG show the same
elements. Module: `romtool/drawings.py` (stdlib only).

- `GET /projects/{pid}/one_line.svg` and `.../one_line.png`: run the cascade
  solve first and return 422 with the errors when it fails, as `/cascade/solve`
  does.
- `GET /projects/{pid}/floors/{fid}/layout.svg` and `.../layout.png`. Add
  `?include_image=false` to leave out the plan background.

The one-line diagram runs left to right from the sources. Each antenna gets a
row, and each parent sits centred on its children, so boxes do not overlap. Boxes
show the source, repeater, remote (max output), splitter (ways and insertion
loss from `parts`), tapper and coupler (part loss) and antenna (port power).
Cable edges show the cable id and length in m and ft. Fiber edges are dashed.
Port power is the worst band by default. Ports below 0 dBm are drawn in red. On a
multi-floor project each floor gets a labelled band. The title block gives the
element counts and the cable totals.

The floor layout is drawn at the floor's pixel size. It shows the stored plan
image (embedded as a data URI in the SVG), walls, the outline, clutter squares
shaded by class with a legend, and the auto-placed equipment. Cable runs follow
their stored `route` points: coax solid, fiber dashed, one colour per cable id.
The scale bar comes from the floor's ppm.

Limits:
- Port power needs the cascade solve. Without it the diagram draws the tree and
  says so.
- A run that feeds another floor is drawn only in the one-line diagram. The floor
  layout skips it because one end is off the floor.
- The PNG layout enlarges plates up to 1600 px a side by a factor of 2 to 4. It
  does not draw a JPEG background (decoding needs Pillow). The SVG draws both.
- The PNG uses the 3 x 5 bitmap font, so it shows uppercase letters, digits and
  `. - : %` only. Other characters become spaces.
- The one-line PNG uses fixed row heights (36 px per leaf). A 300-antenna tree is
  about 10,800 px tall, so use the SVG for large trees.
- Critical areas are not drawn. Edge and equipment labels are not collision
  checked, so labels on a dense floor can overlap.
- The example drawings in `romtool/examples/` come from a 2-floor office on a
  96 m x 74 m plate, autoplaced with remotes and taps requested at -63 dBm
  (B2_1900 and B12_700). Each floor picks one coupler stage (7 and 10 antennas).
  The 12 dB tap does not win at these counts.

## Plan import and building perimeter

Module: `romtool/perimeter.py` (stdlib only). Config block `perimeter` in
`config/default.json`, grade E with a reference.

**Import.** `POST /projects/{pid}/floors/{fid}/plan` takes a multipart `file`
(PNG, JPEG or PDF), `page` (PDF, 1-based, default 1) and `dpi` (PDF, default
`perimeter.pdf_dpi` 150, lowered so the render stays under 8 megapixels). The
plan is stored as the floor's background image through the same storage as
`/image`; PDF and JPEG plans are stored as gray PNG. The floor's pixel size
becomes the image size. JPEG needs Pillow and PDF needs PyMuPDF, both imported
only when used.

**Scale.** `ppm_source` on each floor is `calibrated` (set by the project or
PATCH), `from_area` (set by a covered area) or `default` (floor created with no
ppm). Floors saved before this change count as calibrated. An area is given as
`area_m2` or `area_sqft` on the plan and trace endpoints, or on
`PATCH .../perimeter`. The scale is then ppm = sqrt(outline area in px / area
m2). With an area, the trace runs twice so the metre-based settings use the new
scale.

**Trace.** `POST .../plan` traces by default (`trace=false` only stores the
image). `POST .../perimeter/trace` re-traces from the stored image and replaces
the outline, so manual edits are lost. Steps:
1. Ink: pixels below `dark_threshold` (128). A work cell of up to 800 cells a
   side is ink when 10 percent of its pixels are dark.
2. Specks and frames: ink components smaller than `min_feature_m` (0.6 m) in
   both directions are dropped (text, symbols, ticks). A component spanning 85
   percent of the page in both directions is dropped as a sheet border
   (`frame_frac`).
   Frame peeling (up to `frame_peel_max` 3 rounds): a closed ink ring spanning
   at least `frame_min_span` (50 percent) of the page in both directions is a
   sheet frame when content lies inside it and at least `frame_blank_frac`
   (50 percent) of its inside ring cells have no other ink within
   `frame_margin_frac` (3 percent of the short side, at least 2 gap distances).
   Furniture and columns count as content, specks included. Peeled rings are
   removed and the flood fill runs again, so a double border peels in two rounds.
   The result reports `frames_peeled`.
3. Gap close: ink is dilated by `gap_m` (1.0 m), so door and window gaps up to
   about 2 m close.
4. Flood fill from the image border. Everything not reached is footprint, so
   interior walls, holes and courtyards are ignored.
5. Regions: the largest `keep_regions` (1) footprints with at least 5 percent
   of the largest area are kept. Several kept regions give their convex hull,
   with a warning.
6. Erosion by the same radius moves the boundary back to the outer face of the
   walls. The outer loop is followed along cell corners, simplified with
   Douglas-Peucker (`simplify_m` 0.3 m), and edges within 3 degrees of
   horizontal or vertical are straightened.
If the trace covers more than 90 percent of the page, the request returns 422.
Without a scale the metre values use pixel fallbacks (`gap_frac_unknown` 0.03 of
the short side) and a warning says so.

**Box (region of interest).** The plan and trace endpoints take `roi`: a box
`[x0,y0,x1,y1]` or a polygon `[[x,y],...]` in image pixels (a JSON string on the
plan endpoint, a JSON field on the trace body). Everything outside the box is
blank paper before thresholding, so sheet borders, title blocks and other
drawings outside the box are ignored. The box is stored on the floor and a
re-trace reuses it; `roi: null` clears it, and a new plan import without a box
clears the stored one. If ink crosses a box edge (dark one pixel inside and one
outside, at least `roi_cut_min_px` pixels), the result carries a warning: the
building is cut by the box. Enlarge the box. In the UI, the **Building box**
tool drags the box and traces inside it.

**AI box proposal (optional, off).** `POST .../perimeter/propose-roi` sends a
downscaled copy of the stored plan to the configured AI gateway, takes the box it
returns and traces inside it. It needs `config/ai.json` `perimeter_roi.enabled`
set to `true` and a working gateway; otherwise it returns 503. The manual box
and the trace endpoint do not need it.

**Speck rule.** A small ink component (under `min_feature_m` in both directions)
is dropped only when no other ink lies within half a gap distance of it. Columns
and short wall pieces a gap apart stay and form the wall line. Text and symbols
standing alone are still dropped. Text that touches a wall is kept, so draw a box
that leaves title blocks and dimension strings outside it.

**Edit.** `PATCH .../perimeter` with `{"points": [[x, y], ...]}` replaces the
outline, `{"nudges": [{"index", "dx_m", "dy_m"}]}` moves single vertices
(`dx_px`/`dy_px` without a scale), `{"clear": true}` removes it, and
`{"area_m2"}` or `{"area_sqft"}` sets the scale from the current outline. The
method becomes `manual`. `GET .../perimeter` returns the outline, area, scale
and warnings.

**Use.** The outline is `floor.outline`, so autoplace (antennas stay inside it),
the clutter-map exterior and the floor layout all use it. The layout draws the
plan image, a bold solid perimeter and the equipment. Walls are drawn only when
the floor has walls.

**Limits.**
- The outer loop is the largest closed ink loop. A drawn plate, site or sheet
  rectangle that closes around the building, or a building whose exterior is
  not closed by walls or thin lines, is traced instead of the building. Check
  the overlay after each trace. A manual outline is the fix.
- An open exterior (a gap wider than about 2 m) gives a thin outline of the
  walls that remain. Only the area is checked, against the page size.
- Solid text blocks or text touching a wall stay in the trace. Diagonal or curved
  exteriors are followed on the work grid, not exactly.
- Scale from area is only as good as the outline it is measured from.
- The work grid is at most 800 cells a side, so the trace is accurate to about
  one work cell, which is about 1/800 of the image's larger side.
- Peeling needs the frame to be a ring of its own. A frame whose ink touches
  the building's exterior (a rectangle drawn against the building) forms one
  connected component with it and is not peeled. Use a manual outline there.
- Pure-Python decoding and tracing take several seconds on a full-size page.
- Floors with a clutter map keep the old map after a new plan. Run the
  clutter-map endpoint again.

## BOM export, parts catalog and assembly builders

The project BOM combines three sources: the element BOM (cable per type in metres and feet, connectors, splitters, tappers, couplers, antennas, branch hardware and head-end units), the builders stored on the project, and the parts catalog that maps each role to a part. `GET /projects/{id}/bom` returns the combined `items`. `/exports/projects/{id}/bom.csv` and `bom.json` use the same list.

### Parts catalog

`config/parts_catalog.json` maps each role (`cable.coax_1_2in`, `splitter.2way`, `antenna.omni_das`, and so on) to a manufacturer, model, description, iBwave type and unit. The defaults come from ANS quote history: the part used on the most jobs for the role, with the job count in `source`. A role with no usable history has an empty `model` and the source `no ANS standard yet`. Remotes and head-end units stay generic (`oem.remote`, `oem.source`, `oem.repeater`) until OEM packages are added. The catalog holds identifiers and descriptions only. `tests/test_builders.py` fails if a price or cost field appears in it.

### iBwave equipment list

`GET /projects/{id}/bom_ibwave.csv` and `.xlsx` write an equipment list in the column order of the estimating tool's BOM Import paste zone:

`Type | Manufacturer | (blank) | Model | Description | (blank) | (blank) | Inventory# | Qty`

The file has one header row and one row per part, with quantities summed across floors. Cable is counted in feet, and the metre rows of the element BOM are skipped. `?by_floor=true` adds a `Floor` column after `Qty` and writes one row per part per floor; builder lines are filed under `Site`. An element whose role has no catalog part returns 422 until the role is added to the catalog. The `Type` strings are ROMtool's labels for iBwave classes and should be checked against the iBwave library before the first import.

When the BOM comes from ROMtool, leave the estimating tool's takeoff modules 3a to 3e empty so the same parts are not counted twice.

### Assembly builders

`POST /projects/{id}/builders/{name}` stores the inputs on the project and returns the lines the builder produces. `GET /projects/{id}/builders` lists the stored builders with their lines. Stored builders add their lines to the project BOM under the category `builder: {name}`. Each quantity rule sits in the `builders` block of `config/default.json` with its grade (E or C) and reference.

```
curl -s -X POST $BASE/projects/1/builders/rooftop -H "Content-Type: application/json" -d '{"carriers": ["Carrier A", "Carrier B"]}'
```

| Builder | Inputs | Lines and limits |
|---|---|---|
| `rooftop` | `carriers` (list) or `donor_count`; `mount` `roof` (default) or `wall` | Per donor line: donor antenna, donor mount, roof or wall base, surge arrestor, grounding kit, two weatherproofing kits, 150 ft outdoor-rated 1/2 in coax, 150 ft indoor plenum 1/2 in coax, connectors and jumpers. One roof entry per building. Donor coax per carrier is the ANS standard (grade C). No link budget is checked. |
| `closet` | `racks`, `fiber_runs`, `ladder_ft`, `ground_cable_ft` | Two-post rack, backboard and PDU per rack, ground bar and ground cable, fiber panels, splice cassettes (one per fiber run), fiber housing, fiber jumpers, labels. Head-end units are not repeated: the closet adds one shelf and one label per unit the element BOM already counts. The rack, backboard, ladder rack and ground cable have no ANS part yet, so those lines carry no model. |

### Grades and budget brands

Each project has a `grade` and a `budget_brand`. The grade is `carrier` (default), `enterprise` or `budget`. The brand is `techwave` (default) or `cheapest`, and it only applies when the grade is `budget`. Set both with `PATCH /projects/{id}`, for example `{"grade": "enterprise"}`. The BOM, the BOM CSV and JSON, the iBwave CSV and XLSX, and the builder endpoints accept `?grade=` and `?budget_brand=` for a single request. A value outside the list returns 422. The BOM panel has the same two controls.

The project can also carry `bands`, a list of band ids from `config/default.json`. Without it, every configured band is checked.

| Grade | Tappers and couplers | Omni | 1/2 in cable and connector |
|---|---|---|---|
| carrier | Microlab/FXR DN-xxFE tappers, Microlab/FXR CC-6xxE couplers | CommScope CMAX-O-43-UW-i53 | HL4RPV-50 with JMA UPL-4MT-12 |
| enterprise | Median-ranked compliant part per role and tap ratio | Median-ranked compliant omni | RFS LCF12/ICA12 family, median connector WCW-43M-LCF12-D01, no cable model on file |
| budget, techwave | Techwave part at the exact ratio; otherwise the fallback chain | Techwave TC AI698-2700V05i360B | Techwave N connector TC-CN-N-J-1/2-RC-1 with the ICA12 family cable, to confirm |
| budget, cheapest | Lowest-ranked compliant part per role and tap ratio | Lowest-ranked compliant omni | RFS 43M-LCF12-E01, no cable model on file |

Candidate lists come from ANS quote history (parts on 2 or more jobs). They live in `config/grades.json` with the source and job count on each row. Band ranges, tap ratios and interfaces are taken from the description when it states them. `budget_rank` orders the candidates and is not catalog data.

A part is compliant when its stated range covers each project band centre frequency (`freq_mhz` in the band config). A part with no stated range is not compliant for any band. Connectors are checked by cable family and interface, not by band.

When the budget Techwave part is not compliant or the exact tap ratio is missing, the selection moves to the cheapest compliant part, then enterprise, then carrier. The carrier part is the last resort and is kept even when it does not cover a band. The note on that line says which band it misses. Each affected line carries a `note` in the BOM JSON and the builder responses, and `grade_notes` lists the notes for the project. The iBwave file has no note column, so the notes appear only in the JSON and on the BOM panel.

Tap and coupler losses are not changed. Each tapper or coupler line is counted by its modeled loss (the element's own `tap_loss_db` or `coupled_loss_db`, otherwise the config default), so elements with different losses get separate lines. The line uses the nearest ratio the selected family offers, and ties go to the lower ratio. The note gives the modeled and part values. The cascade still uses the modeled loss, so the note marks where the physics and the part differ.

The grade applies to the element BOM and builder lines that carry the 1/2 in cable: the 1/2 in cable and its connectors, branch connectors when the branch cable is 1/2 in, the rooftop plenum leg and GPS coax. It does not apply to the 7/8 in trunk, LMR-400, the outdoor donor run (LDF4-50A), splitters, jumpers, mounts, surge arrestors, fiber or head-end units.

Open items:
- Carrier couplers are not in the grade brief. They use the Microlab CC-6xxE family, the same vendor as the carrier tappers, and need owner confirmation.
- The Techwave N connector has no description on file. The budget Techwave pairing assumes the ICA12 family.
- The budget Techwave grade mixes N-type omnis and couplers with the 4.3-10 fallback tappers.
- Splitter TC-MSCoM-02NF is not wired because it has no band range or candidate row.
- ANS data has no ICA12 or LCF12 cable model, so enterprise and budget lines show the cable with an empty model.

## Area zones (mixed-use floors, ceiling height and pathway)

A floor can hold named zones: a rectangle or polygon with a zone class. A zone
sets the clutter for the squares it covers, so an office with an attached racked
warehouse scores correctly without drawing walls, and it sets the ceiling height
of antennas inside it. Zone values are mostly grade E estimates.

### Using zones

- In the UI, pick the **Zone** tool. Set the class, name, height and pathway in the
  Zones panel first. Drag a rectangle, or click corners and close the shape with
  **Finish polygon** or a click on the first corner.
- Select a zone with the Select tool to edit its name, class, height or pathway in
  the inspector, or to delete it (Delete key or **Delete zone**).
- API: `GET` and `POST` on `/projects/{pid}/floors/{fid}/zones`, and `PATCH` and
  `DELETE` on `.../zones/{zid}`. `POST` takes one zone or `{"zones": [...]}`. Body
  fields: `name`, `class`, `rect` as `[x0, y0, x1, y1]` or `points` as
  `[[x, y], ...]` in floor canvas px (the coordinates of walls, antennas and critical
  areas), and the optional overrides `height_band`, `ceiling_height_m` and `pathway`.
  A `null` override clears it. Each zone gets an `id`. Responses show the effective
  `ceiling_height_m`, `height_band` and `pathway`, and `height_source` and
  `pathway_source` say where each came from.
- `GET /config` returns the zone classes under `clutter_map.classes`, the height bands
  under `clutter_map.ceiling_height_bands` and the pathways under
  `clutter_map.cable_pathways`.

### Zone classes

Zone classes are clutter classes in `config/default.json` (`clutter_map.classes`).
The ten classes below are new. The five scoring classes (open, light_office,
dense_rooms, core, exterior) are unchanged. Grade C means the dB/m value is the
calibrated building type value. Grade E values are starting values taken from the
named building type and are not calibrated.

| Class | Code | dB/m | Grade | Source of the value | Default height | Default pathway |
| --- | --- | --- | --- | --- | --- | --- |
| warehouse_racked | r | 1.0 | C | building_types.warehouse_open (4 ANS warehouse designs) | Over 20 ft (lift) | Open ceiling / exposed |
| high_bay_open | h | 0.1 | E | starting value of class open (no high-bay source) | Over 20 ft (lift) | Open ceiling / exposed |
| office_open | a | 0.1 | E | building_types.office_open | Up to 10 ft | J-hook above drop ceiling |
| office_standard | s | 0.3 | C | building_types.office_standard (12 ANS office designs) | Up to 10 ft | J-hook above drop ceiling |
| office_dense | e | 0.6 | E | building_types.office_dense | Up to 10 ft | J-hook above drop ceiling |
| hospital_rooms | p | 0.6 | C | building_types.hospital (12 ANS hospital designs) | Up to 10 ft | Hard lid ceiling |
| hotel_rooms | t | 0.4 | C | building_types.hotel_residential (4 ANS designs) | Up to 10 ft | Conduit pull |
| retail | i | 0.0 | E | building_types.retail_mall (not calibrated) | 10 to 15 ft | Cable tray |
| parking_garage | g | 0.0 | E | building_types.parking_garage (not calibrated) | Up to 10 ft | Open ceiling / exposed |
| stadium_bowl | y | 0.0 | E | building_types.stadium_venue (not calibrated) | Over 20 ft (lift) | Cable tray |

Each class code is one character and unique. `_` is reserved for the fallback
square of a zones-only grid.

Height bands (`clutter_map.ceiling_height_bands`, all grade E): Up to 10 ft is 3.0 m,
10 to 15 ft is 3.8 m (midpoint), 15 to 20 ft is 5.3 m (midpoint), and Over 20 ft (lift)
is 7.6 m (25 ft). Pathways (`clutter_map.cable_pathways`): J-hook above drop ceiling,
Cable tray, Conduit pull, Open ceiling / exposed, Hard lid ceiling, Vertical riser,
Exterior / rooftop.

### What a zone changes

- Clutter. A square takes the zone class when its centre lies in the zone. Later
  zones win where zones overlap. Zones also override the automatic square class and
  any manual square override in the same area. Squares outside every zone keep the
  floor's automatic clutter class. A floor with zones and no clutter map gets a grid
  built from the zones alone (`cell_m` squares, no image needed). Squares outside
  every zone take the floor's building type clutter, or 0 when no building type is
  set. As with the clutter map, zones apply only when the floor has no walls drawn.
- Antenna height. An antenna inside a zone sits at the zone's ceiling height. The
  distance term in predict and autoplace uses the slant distance
  `sqrt(d_h^2 + dv^2)`, where `d_h` is the horizontal distance and `dv` is the ceiling
  height minus `autoplace.floor_height_m` (4.0 m). The path exponent N and the clutter
  term (horizontal path) are unchanged. Antennas outside every zone, and all antennas
  on a floor without zones, have `dv` = 0 and predict the same values as before.
  Antennas on other floors get no height offset. Heights apply with or without walls.
- Autoplace result. Each entry in `antennas` gives `zone_id`, `zone_name`,
  `zone_class`, `ceiling_height_m`, `height_band`, `pathway` and `height_offset_m`.
  Seed spacing uses the zone height that reaches least far. The coverage window uses
  the height that reaches furthest, so no contribution is cut early.
- Pathway. Recorded and reported only. It does not change RF results or BOM quantities.
- Drawings. `layout.svg` and `layout.png` fill each zone by class, outline it, and
  label it with name, class and height. The legend lists the zone classes present.

### Limits

- Only the warehouse, office standard, hospital and hotel values come from ANS
  calibration (grade C). Every other zone value is a starting estimate. Zone ceiling
  heights are estimates, not measurements. Calibrate against closed jobs before relying
  on zone counts.
- Height enters as one vertical term in the distance. There is no per-band height,
  no reflection or ceiling geometry, and the floor baseline (4.0 m) is grade E.
- An antenna takes the zone its point sits in. A zone smaller than one square covers
  no square, and the map reports that as a warning.
- Zones are rectangles or polygons in floor canvas px. They are not drawn on the plan
  image and do not move with it. Holes and curved boundaries are not supported.
