How it works: the math behind every number

Every formula, table and worked example below is the implementation in romtool/ (physics, cascade, predict, composite) and matches the pytest hand-math anchors in tests/. The workflow is on How-To; all numeric defaults live in config/default.json and are editable. Cited standards are references for the model shapes, not compliance claims: thresholds, buckets and area percentages here are editable planning defaults.

Model overview, and what accuracy to expect

ROMtool is a rough-order-of-magnitude estimator. Per band, per floor grid point:

  1. solve the DAS cascade (per-antenna port power and EIRP, §cascade),
  2. path loss per antenna-to-point ray: ITU-R P.1238 distance term + floor term, plus P.2040-scaled wall-crossing losses on the same floor (§path loss, §walls),
  3. per-antenna RSSI = EIRP - path loss; composite = linear (mW) sum over co-channel antennas (§RSSI & composite),
  4. KPIs from threshold coverage, incl. NFPA two-tier with critical-area polygons and the 5G NR SS-RSRP classes (§KPIs),
  5. multiband composite = per-point best band, union KPI = OR across bands (§composite).

Empirical grade, relative accuracy: there is no ray tracing, no diffraction, no multipath fading, no capacity modeling. Numbers are for system shape, budget sanity and antenna-count ROM - not bid guarantees. Verify with a site survey / acceptance walk test.

1. Cascade link budget (per band)

The chain graph is built from the project elements: nodes are source, repeater, splitter, tapper, coupler, antenna; edges are cable_run elements (from_id → to_id, cable type, length). The solver walks the graph breadth-first from every source, accumulating dBm per node per band.

1.1 Sources

  • Off-air donor (default): out = ambient + donor_gain - inline_feeder_loss (dBm). Ambient defaults to the band's config value (-85 dBm on the default set); per-element ambient_dbm overrides, per band.
  • Direct inject (subtype: direct): out = injection_dbm (element, else the subtype default +5 dBm). Ambient and donor gain do not apply.

1.2 Cables: anchors, log-domain interpolation, clamps

Cable loss is tabulated as dB/100 m at anchor frequencies and interpolated linearly in the log-frequency domain (the same domain as the P.2040 wall-loss scaling); loss = per100 * length_m / 100. Outside the anchor range the value clamps to the nearest anchor - exact at the anchors, conservative below 0.7 GHz (real low-band loss is lower than the 0.7 GHz value).

Shipped anchors (dB/100 m, representative - edit per cable datasheet):

Cable0.7 GHz0.92.03.04.0

Log-domain interpolation properties (test-verified): between anchors 10 dB/100m @0.7 GHz and 20 @2.0 GHz, the frequency midway in log domain - the geometric mean sqrt(700 * 2000) = 1183.2 MHz - evaluates to exactly 15.0 dB/100m; a 400 MHz request clamps to 10.0. On the example project, 2.0 m of LMR-400 at 763 MHz interpolates to 11.81 dB/100m → 0.236 dB, and the solve trace for the donor feeder run shows exactly that.

1.3 Devices

  • Repeater/BDA: out = min(in + dl_gain_db, max_dl_out_dbm), warning when clamped; per-band gain via dl_gain_db_per_band; trunk branches may not exceed ports.
  • Splitter: every branch = in - insertion loss (2-way 3.5 / 3-way 5.5 / 4-way 7.5 dB shipped defaults, or per-element il_db).
  • Tap: branch on the through port = in - through_il_db (0.8); branches on the tap port(s) = in - tap_loss_db (12.0). Coupler: same with through/coupled roles (0.6 / 10.0).
  • Antenna: port = min(arrival, max_port_dbm) (capped = warning), and EIRP = port + gain_db. A port below 0 dBm raises a loss-budget warning. Antennas terminate the chain.

1.4 Worked hand example (the pytest arithmetic, verbatim)

From tests/test_cascade.py, at a simplified part set used by the test bench (f = 2000 MHz, ambient -85 dBm, donor gain 11 dBi, feeder 0 dB, repeater gain 25 dB / max 33 dBm, test cable exactly 20 dB/100m, 2-way splitter IL 3.2 dB, antenna gain 2 dBi):

source out   = -85 + 11 - 0                    = -74.0 dBm
feeder loss  1.0 m @ 20 dB/100m                =   0.2 dB
repeater in  = -74.0 - 0.2                     = -74.2 dBm
repeater out = min(-74.2 + 25, 33)             = -49.2 dBm   (no clamp)
trunk loss   2.0 m                             =   0.4 dB
splitter in  = -49.2 - 0.4                     = -49.6 dBm
per branch   = -49.6 - 3.2                     = -52.8 dBm
A1: in = -52.8 - 0.2 = -53.0 dBm -> port -53.0 -> EIRP -51.0 dBm
A2: in = -52.8 - 0.3 = -53.1 dBm -> port -53.1 -> EIRP -51.1 dBm

Tap/coupler variant of the same bench: repeater out -49.2 → tap branches -58.2 (tap loss 9.0), through -49.7; coupler coupled port -57.7 (coupled 8.0), through -50.1. Clamp variant: repeater max out -80 → A1 in = -80 - 0.4 - 3.2 - 0.2 = -83.8 dBm. 3-way splitter (IL 5.4): branch -55.0, so runs of 1.0 m land at -55.2 and 0.5 m runs at -55.1.

The shipped config defaults differ (repeater 65 dB gain / 33 dBm max out, 2-way IL 3.5 dB, LMR-400 etc.), which is why the example project's Band-14 solve reads: SRC out -74.0 → RPTR in -74.24 (2.0 m LMR-400 @763 MHz = 0.236 dB) → out -9.24 (-74.24 + 65, under the 33 clamp) → SP1 in -9.67 (8.0 m 7/8 in = 0.432 dB) → branch -13.17 (3.5 dB IL) → ... → A1 in -17.67 → EIRP -15.67 dBm.

2. Path loss

2.1 Free-space sanity model (FSPL)

FSPL(dB) = 20 log10(d_m) + 20 log10(f_MHz) - 27.55 - kept in the engine as the sanity anchor only. Test anchors: FSPL(1 m, 2000 MHz) = 38.47 ≈ 38.5 dB; FSPL(10 m, 1900 MHz) = 58.03 ≈ 58 dB. Doubling distance adds exactly 6.02 dB.

2.2 ITU-R P.1238 indoor model (the distance term actually used)

PL(dB) = 20 log10(f_MHz) + N * log10(d_m) + Lf * n_floors - 28

  • N per environment (config, editable):
EnvironmentN (default)
Office30
Commercial / retail22
Residential28

Sub-400 MHz LMR bands ship with per-band N overrides (chosen to be conservative at low frequency): VHF 150 MHz → office 34 / commercial 26 / residential 32; UHF 450 MHz → 32 / 24 / 30. A per-band override always wins over the environment value, and the predict response reports which source answered (n_exponent_source).

  • Floor term: Lf = 15.4 dB per floor separation (config), applied per level between the antenna's floor and the prediction floor - linear, so 2 floors = 30.8 dB. Inter-floor antennas skip the wall-crossing sum entirely (the slab dominates).
  • Shape sanity: with N = 20 (free-space slope) and same floor, P.1238 = FSPL - 0.45 dB (the -28 constant vs -27.55). Test-asserted.
  • Distance clamp: distances below 1 cm are clamped to 1 cm so log10 stays finite.
  • Worked example (test-asserted): 750 MHz, N = 30, 10 m, same floor: 20 log10(750) = 57.50 → 57.50 + 30 * log10(10) - 28 = 59.50 dB.

1 m reference points (N = 30, same floor) for the shipped NR bands: n71 634.5 MHz → 28.05 dB; n41 2593 MHz → 40.28 dB; n77 3840 MHz → 43.69 dB.

3. Wall crossings (P.2040-scaled)

3.1 Tabulated losses and frequency scaling

Materials are tabulated at wall_loss_ref_mhz = 2000 MHz and scaled linearly in the log-frequency domain (the P.2040 curve rule):

A(f) = A(2 GHz) * log10(f) / log10(2000)

Exact at the reference, lower at low bands, higher at C-band. Shipped table and scaled values (dB):

Concrete 15 dB @2 GHz evaluates to 12.93 dB @700 MHz, which tracks the published P.2040 trend for concrete (~13 dB at 700 MHz, test-asserted window 12.8-13.1).

3.2 The wall-crossing model

  • For each same-floor antenna → grid-point ray: count every strict interior intersection between the straight segment and the wall segments (open-interval test, 0 < t < 1 and 0 < u < 1). A point lying exactly on a wall (shared endpoint) is not counted - this keeps 1-px grids from double counting. Walls outside the ray's bounding box are rejected first (performance only).
  • Total wall loss per point = sum over crossed walls of each material's scaled loss. Examples (test-asserted): one drywall + one glass at 2 GHz = 9.0 dB; two parallel concrete = 30.0 dB; a wall ending short of the ray (shared y) adds 0.
  • Same floor only: antennas on another level replace the crossing term with the floor term 15.4 dB x level delta (test-asserted: one floor up shifts every value by exactly 15.4 dB).
  • Optional per-band wall_loss_scale_db adds a constant decibel correction to every scaled crossing (calibration knob; VHF ships +2.0, UHF +1.0; test-asserted: +6.0 shifts crossing-column points by exactly 6 dB).

This is a single straight-ray wall-count, in the family of multi-wall models (cf. COST 231 Multi-Wall) with per-segment material loss and log-frequency scaling per P.2040 - a deliberate simplification: no ray tracing, no diffraction around corners.

4. Per-antenna RSSI and the composite sum

Per antenna per grid point:

RSSI = EIRP_dBm - PL_total

where PL_total = P.1238 (const 20 log10 f + N log10 d + floor term) + wall crossings (same floor). Composite over co-channel antennas is a linear (mW-domain) sum:

composite = 10 log10( SUM 10^(RSSI/10) )

Test anchors: -90 and -100 dBm combine to -90 + 10 log10(1.1) = -89.59 dBm; two equal carriers add +3.01 dB; order-independent; empty = None. Rounding: grid values are stored to 0.1 dB.

Best server per point = the strongest single-antenna RSSI (exact ties resolve to the first antenna in the chain). The values_dbm grid is the composite; best_server is the winner grid.

One clamp to know about: near an antenna the distance clamps to 1 cm, so PL can go slightly negative (at 2 GHz, N = 30: PL(0.01 m) = -21.98 dB). Physically meaningless, only visible at grid points co-located with an antenna; it never affects real coverage areas.

5. KPI math

5.1 Threshold coverage

The floor is sampled at grid points (col*step, row*step) px. A point is covered when composite >= threshold (default -95 dBm, exact with 1e-9 tolerance). Coverage % = covered points / total points of the grid rectangle - the whole floor canvas, walls included (grid-point approximation of area, no sub-cell weighting).

Worked example (test-asserted): a 3x3 px room at 1 px/m, one antenna, tuned so the 1 m points sit exactly 0.01 dB above T = -94.8 dBm. P.1238 (2 GHz, N = 30): PL(0.01 m) = -21.98, PL(1 m) = 38.02, PL(1.414) = 42.54, PL(2) = 47.05, PL(2.236) = 48.51, PL(2.828) = 51.57 dB. Exactly {(0,0), (1,0), (0,1)} clear the threshold → 3/9 = 33.33%.

5.2 NFPA two-tier with critical-area polygons

The default preset (editable; shown with shipped values):

TierScope (default)ThresholdMin area %
Tier 1 (general)whole floor-95 dBm95%
Tier 2 (critical-area)inside critical-area polygons-95 dBm99%
  • Tier 2 membership is a ray-casting point-in-polygon test on the grid points; a point on a polygon edge counts as inside (documented approximation). Multiple polygons evaluate as a union - a point inside two polygons counts once - and the report carries per-polygon rows so a failing room is identifiable.
  • Test arithmetic (9-point room, L-shaped polygon covering point indices {0, 1, 3}): tier 2 n_points = 3, covered = 3 → 100% → pass; the same floor without points in the polygon (far-corner polygon) → 0% → fail. Overlapping polygons: a contained point counts once in the union (9 points, not 10).
  • No polygons drawn → tier 2 falls back to whole-floor evaluation with an explicit note. A tier's scope can be forced with a scope config field (whole_floor / critical_areas).
  • Reference concept: the two-tier critical-area evaluation used for ERCES acceptance (NFPA 1225 / IFC 510 family). The thresholds/percentages here are editable planning defaults; the AHJ defines the binding criteria, and this tool makes no compliance claim.

5.3 5G NR SS-RSRP preset and class buckets

Bands carrying technology: "5G NR" are additionally evaluated on an SS-RSRP estimate = composite carrier RSSI + optional per-band ss_rsrp_offset_db (a per-RE conversion, order -10 log10(number of resource elements of the carrier); default 0). The single-tier/NFPA tiers stay on raw composite RSSI.

  • Threshold KPI (whole floor): default -95 dBm at 95%.
  • Class buckets (editable planning defaults, NOT normative 3GPP classes; disjoint by construction):
ClassSS-RSRP range (dBm)

Worked example (test-asserted verbatim) - 9-point room, 1 px/m, EIRP -60 dBm on a 2000 MHz NR band, no walls, N = 30:

(0,0) d = 0.01 (clamped): RSSI = -60 - (-21.98) = -38.02 -> excellent
(1,0) (0,1) d = 1 m     : RSSI = -60 - 38.02   = -98.02 -> fair
(1,1) d = 1.414 m       : RSSI = -102.54                  -> edge

Each row shows as % of floor area; buckets sum to 100% (test-asserted). With ss_rsrp_offset_db = -10, the same floor reads excellent 11.11 / edge 22.22 / none 66.67 - the offset applies only to the SS-RSRP view, not to the LTE-style tiers.

6. Multiband composite (best-band) view

Selected bands are predicted on the same pixel grid, then combined per point:

  • Composite value = element-wise max across bands - not a linear RF sum. Different carriers are not co-channel; the signal never combines. The honest question is "which band serves this point, and how strong".
  • best_band / best_server name the serving band and antenna of the point maximum.
  • Union KPI (OR semantics): a point counts when any selected band is at/above that band's own single-tier threshold; the pass flag is against the single-tier min area % (95 default). When all selected thresholds are equal (the usual case), the report exposes one uniform threshold.

Why best-band flips behind walls (test-asserted formulas): away from walls the per-band values differ by

value_A - value_B = (EIRP_A - EIRP_B) + 20 log10(f_B / f_A)

Example: band A @2600 MHz at EIRP -60 vs band B @3840 at -55: delta = -5 + 3.3872 = -1.61 dB → B (higher EIRP + frequency advantage) serves everywhere. Behind a metal wall (30 dB tabulated, 31.04 @2600 vs 32.57 @3840) B's extra 1.54 dB of wall loss flips the delta to +0.93 dB on the crossing column → A serves there (test-asserted to 3 decimals: -0.6128 / +0.9263).

On the example project the 3-band NR composite (N71/N41/N77, step 4) reports union 690/690 = 100% with per-band KPIs all passing; each NR band also carries its full SS-RSRP block end to end.

8. Documented deviations and limitations

  • No ray tracing (by SPEC): one straight antenna→point ray, wall-count only. No diffraction, reflection re-convergence, corridor guidance or fading statistics. Expect ROM-level scatter against measurements.
  • Empirical grade, relative accuracy: models (P.1238 + P.2040 + multi-wall counting) are calibrated families, not site-validated predictions. Use per-band N / wall-scale overrides to bias-correct against walk data.
  • Whole-floor KPI rectangle includes wall pixels and outside-true-floor areas; critical-area polygons are evaluated at grid-point resolution (edge points inside). Comparisons to walk tests should note both.
  • Composite sum assumes co-channel antennas; best-band views deliberately use max/OR instead (different carriers). Do not read the multiband composite value as an interference-weighted level.
  • SS-RSRP here is composite carrier RSSI (+ optional per-band offset), a ROM stand-in for 3GPP SS-RSRP per-RE measurement - not a demodulated measurement, and the class buckets are editable planning defaults.
  • Single-carrier DL per band: port powers are per-band, single-carrier estimates; no multi-carrier power sharing, no uplink, no capacity/Monte Carlo.
  • Grid step changes sampling density; KPI % between different steps can differ slightly. Use step 1 for reported numbers.
  • Everything numeric is data: config/default.json globally, plus per-project config_overrides (deep-merged). Bands, environments, materials, cables, parts, presets and report colors are all entries there - adding e.g. an n78 3.3 GHz band needs no code change.

10. Class 1 estimate math (Phase 4)

The labor estimator prices builds from a labor-unit catalog (config/labor_units.json, 134 rows, zones A-Rooftop … O-DC-Power-Plant) with every numeric constant in config/estimating.json: factor values, ratios, the rate card, contingency bands. mids are (low + high) / 2 of each catalog or config range. The full chain, in stacking order:

10.1 Factor stack: base minutes → task hours

Per line: base minutes = qty × unit minutes (low/mid/high) → × condition factors → × access factor → × schedule premium = task hours (stage 4). Condition rows: M03 occupied 1.25-1.5 (mid 1.375), M04 weather-exposed 1.2-1.4 (mid 1.3), M07 freight/escort constraints 1.2-1.4 (mid 1.3) (multiple flags multiply). Schedule rows (M02): night 1.25-1.4, weekend 1.25-1.5 (both multiply). Access methods map to catalog factor rows: ground = 1.0, ladder = K06 1.15-1.25 (Durand difficult column above 12 ft), lift = K03 1.25-1.5, scissor = K03 1.1-1.25 (faster positioning), rope = K05 1.5-2.0. Worked example — catalog row A01 (donor antenna install, 60-120 min) x1 on a rope-access exterior roof at night: base mid 1.5 h × 1.3 (M04) × 1.75 (K05) × 1.325 (M02) = 4.5216 task hours.

K-Access-ADDERS rule: K-zone minute rows (K01 lift setup, K02 relocations, K04 rope rigging, K07/K08/K10/K11/K13, crane rows) never take the access factor themselves — they are the access adders; condition and schedule factors still apply to them.

10.2 Supervision and wrap: task hours → wrapped hours

Stage 3 adds two supervision components to task hours. N01 working foreman: a working foreman produces at a 0.5 productive-time haircut while supervising, so a 4-techs + 1-foreman crew adds (1/4) × 0.5 = +12.5% of task hours as foreman hours (billed at the foreman rate). N02 non-working supervision adds 8-15% (config 0.08-0.15 as a fraction, mid 11.5%) of task hours as super/PM labor (foreman rate). Applied to the example: 4.5216 × 1.24 = 5.6067 wrapped hours — the 1.24 multiplier = 1 + 0.125 + 0.115. Then the estimate-level wrap is added as derived lines that carry base minutes with no stacking (they ARE the wrap): M05 travel moves (from travel_moves), N03 owner orientation (crews × locations; each location counts as one phase), N04 daily cleanup (qty = crew-days). M01 rows are different again: downtime_windows blacked-out days carry cost, not hours — per day, crew size (5) × 8 h × blended rate 89 $/h = $3,560, where blended = (4×$85 + 1×$105) / 5 = 89.

10.3 The 48VDC power-plant auto-sizer (O zone)

A location's optional power_plant block auto-derives catalog lines: plant bay O01 x1; rectifiers O02 = N+1, i.e. ceil(load_amps / 50 A) + 1 spare (30 A → 2 modules); battery strings O04 = ceil(Ah / 120 Ah) where Ah = runtime_hours × load_amps (12 h × 30 A = 360 Ah → 3 strings), per the IFC 510.4.2.3 12-hour runtime minimum — a runtime below 12 h emits a recap warning. Optional spill_containment / battery_monitoring derive O05 / O06 per string; rectifier_modules pins the count manually. The O-zone row set supersedes B05/B06 at detail level.

10.4 The $ chain

Wrapped lines bill task hours at the burdened tech rate ($85/h) and the foreman + super hours at the foreman rate ($105/h). Rollup order (per low/mid/high band): direct labor → + M01 downtime carry → I05 project management (10% of accepted labor) → overhead (10% of the above) → profit (10% of the above) → N05 line-risk contingency per line by catalog source-quality — P 3% / E 7% / G 10% — on labor dollars only, never on markups → grand total. Crew stats: crew-days = ceil(direct wrapped hours / (crews × (techs + foremen) × hours_per_day)) — 40 h/day for a 1x5 crew; crew-week = crew-day × days_per_week (200 h/week); the recap reports crew-weeks and average hours per crew-week. A worked AACE Class 1 stadium scenario (rope roof, lift bowl, occupied closet, ERCES headend with the power-plant sizer, night differential and a lockout window) is asserted line-by-line against hand math in tests/test_phase4.py.

10.5 Estimate-specific documented deviations

  • Derived wrap/logistics lines (M05/N03/N04) and the M01 carry use no factor stacking; their quantities derive from the crew plan (crew-days from the mid band).
  • N02 supervision hours bill at the foreman rate, not a separate PM rate; I05 PM% is the percent-of-labor markup line.
  • 0-minute DAY/LOT rows are quote carries (recurring service, permits, crane day rates); the engine refuses to price them as hours and derives only M01 from downtime_windows.
  • FACTOR rows are multipliers only — they cannot be posted as lines[] rows.
  • Heavy reels (>100 lb, per K14/Day Wireless note) are crew-plan issues (2-3 techs per pull), not unit-minute adjustments.

References for the estimate side (shapes, not conformance): NECA Manual of Labor Units (normal/difficult/very-difficult hour columns and the K03-style ladder ladder), IFC 510.4.2.3 (12-hour ERCES battery runtime sizing), TIA-607 (bonding scope, O10/J06/C06 split), AACE Class 1 estimate band (the N05 contingency concept: -3/-10 to +3/+15% vs actual, carried as line risk).

10.6 Governance + procurement math (v0.5.0)

  • Line identity: every recap line carries a stable line_id (<location_id>:<catalog_id>, estimate-level lines bare, duplicates suffixed #2/#3, e.g. two M01 windows). Revisions, quote linked_line_ids and the assumption register all key on it, so diffs survive re-computes.
  • Revision diff: recompute the definition, then compare by line_id (qty and wrapped-hours changes), by definition meta paths (schedule.night, crew.techs, locations.<id>.access, ...) and by totals drift. A no-op PATCH still creates a revision — the audit trail records the re-compute with an empty changed_paths list. Totals paths appear only when the value actually moved.
  • Estimate line carry (bid-tab basis): wrapped labor (mid band) + line-risk contingency + idle-cost carry for that line — e.g. the stadium E06 bowl antennas carry 40 × 0.75 h × 1.375 × 1.375 × 1.325 × $110.20/task-h wrapped rate × 1.07 (E-band) = $8,861.51. Whole-estimate (unlinked) quotes compare against the recap grand total ($80,528.33 for the stadium under the v0.6.0 wrap; see §11).
  • Quote binding math: binding_until is inclusive — a received/bound quote stays binding through the date and flips to expired strictly after (computed at read time; the stored status row is never silently mutated, re-issuing an expired quote goes through expired→received). Each expired quote produces exactly one QUOTE_EXPIRED warning per render (“warn once”); binding windows within quote_binding_warn_days of expiry warn early. Bid-tab low/median/high statistics use only active received/bound quotes; mid is the median (mean of the two middle values for even counts).
  • Assumption auto-population: one register row per recap line whose catalog row is a minutes-kind norm flagged E (estimated). The stadium fixture yields 24 rows: 18 definition lines + the derived M05/N03/N04 wrap rows + the auto-sized O01/O02/O04 power-plant rows; G-grade rows (H07, G03) and the M01 cost-carry row are excluded by rule. Revision re-syncs drop only open rows whose line vanished.
  • PDF writer: the inclusions/exclusions PDF is rendered by the zero-dependency romtool/pdf.py writer (PDF 1.4, base-14 Helvetica, uncompressed streams so text stays greppable), with an intentional over-estimate of ~0.55 em per character for line wrapping — lines never clip, pages flow automatically.

11. Commercial wrap order (v0.6.0)

The recap $ chain applies every commercial step in one documented order. Every rate lives in config/commercial.json (editable; nothing hard-coded in the engine) and the same ordered codes ride the recap as cost.wrap_order and the money-lines sequence:

 1. DIRECT_LABOR     wrapped line labor: task + N01 foreman + N02 super
 2. DOWNTIME_M01     idle crew-day carry (schedule risk, zero hours)
 3. SMALL_TOOLS      small_tools.pct x (labor + downtime)
 4. ESCALATION       (index factor - 1) x (labor + downtime)
 5. TAXES            sales_tax rate x taxable wrapped labor (line-type rules)
 6. INSURANCE_BOND   insurance_bond.pct x running subtotal through taxes
 7. PM_I05           pm_pct x running subtotal through insurance/bond
 8. OVERHEAD         overhead_pct x running subtotal through PM
 9. PROFIT           profit_pct x running subtotal through OH
10. CONTINGENCY_N05  per-line labor x pct by source quality (P3/E7/G10)
    GRAND TOTAL      subtotal + contingency

Percentages apply low/mid/high uniformly, each step on its documented basis. Two exceptions, on purpose: escalation always applies to the (labor + downtime) base only — it never rides the small-tools markup — and taxes apply to the taxable wrapped labor per the line-type rules, not to the running subtotal. Contingency stays outside the marked-up subtotal exactly as in v0.4.

11.1 Escalation date math (hand example)

Labor index: base 2026-01-01, annualized rate 3.5%/yr, simple interest on calendar days.
Anchor date 2026-07-02 → days = 182 → factor = 1 + 182/365 × 3.5% = 1.0174521. The stadium's labor + downtime base is $55,240.55 → ESCALATION = $55,240.55 × 0.0174521 = $964.06. Anchor before the index base date never de-escalates (factor 1). With a definition start_date but no explicit anchor, the anchor is the midpoint working day of the with-crews schedule (stadium from Mon 2026-11-16, one crew, 16 work days → the 8th work day = 2026-11-25). No anchor at all → the step is skipped with an explicit warning. Definition commercial.escalation.index selects copper/equipment instead of labor (the labor recap escalates through the chosen index's rate; the copper and equipment scopes exist for material-bearing scope and future phases).

11.2 Taxes, insurance/bond, risk tiers (hand example)

Sales/use tax classifies every recap line by catalog zone prefix via zone_line_types; the shipped default classifies all zones as labor and labor is exempt (real-property improvement), so the stadium taxes $0.00 — reported explicitly with taxable = $0 / exempt = every line + the M01 idle carry. Classify a zone equipment/materials (only when your jurisdiction taxes that base) and the zone's wrapped labor is taxed at the rate (default 7%, per-estimate override via commercial.tax.rate_pct). Insurance & bond carry 1.5% (running subtotal through taxes) and profit by risk tier (low 8 / standard 10 / high 12; definition commercial.profit_risk_tier; an explicit rate_overrides.profit_pct beats the tier). Stadium mid-band hand chain (no anchor): labor $51,680.55 + downtime $3,560.00 → small tools 3% = $1,657.22 → escalation skipped = $0 → taxes $0 → insurance/bond 1.5% = $853.47 → PM 10% = $5,775.12 → OH = $6,352.64 → profit = $6,987.90 → subtotal $76,866.88 + line-risk contingency $3,661.44 = GRAND TOTAL $80,528.33.

11.3 Crew schedule, cash curve, scenarios (v0.6.0)

  • Crew loading: per-location crew-days = ceil(location wrapped mid hours / single-crew daily capacity) (stadium: roof 2 + bowl 11 + closet 1 + headend 2 = 16, vs the whole-estimate ceil of 15 — per-location ceils sum above the global ceil and that is documented, not forced). Working days are the first days_per_week weekdays starting Monday; downtime_windows entries with a start date blackout those calendar days (undated windows still price M01 idle carry but block nothing). Phases are claimed whole by a free crew in definition order; a crew finishing on day D starts the next phase on D+1. GET /estimates/{id}/schedule reports the early bound (all configured crews) and the late bound (single-crew serial), and flags weekly scheduled hours above the double-time threshold (40 h) with the DT multiplier — schedule- level information only; the M02 hour differentials remain the labor-costing mechanism.
  • Cash-flow phasing: the config milestone splits (NTP 10 / DESIGN 15 / INSTALL 60 / COMMISSION 10 / CLOSEOUT 5, must sum to 100) of the wrapped grand total (mid band) build a monthly curve. INSTALL spreads across the calendar months the early schedule spans (or ceil(work days / 21) months without dates). Hand example, stadium with no dates: M0 = NTP 10%; M1 = DESIGN 7.5% + INSTALL 60%; M2 = DESIGN 7.5% + COMMISSION 10%; M3 = CLOSEOUT 5% — splits sum to exactly 100% and amounts to the grand total. GET /estimates/{id}/cashflow + CSV/XLSX exports.
  • What-if scenarios: POST /estimates/{id}/scenarios stores {name, overlay} with four overlay families: access_overrides (per location method), factor_overrides (deep-merged onto the estimating config), qty_overrides (set qty on an existing definition line), quote_swap (a vendor quote's amount replaces the named lines' wrapped labor, allocated proportionally by each line's share of the group carry per band; hours/schedule unchanged and the swap flows through the full wrap chain). Diffs are computed fresh against the current base at read time (GET .../scenarios/{sid}/diff) — only changed lines (qty / hours mid / labor mid) plus the totals delta. Hand example: switching the mini fixture's Loc B from ground to lift (mid 1.375) changes exactly Loc B's lines (hours × 1.375, labor × 1.375) and the grand-total delta carries the wrap amplification (labor delta × 1.03 small tools × 1.015 insurance × 1.1 PM × 1.1 OH × 1.1 profit + 7% line-risk contingency).
  • Bid form: GET /exports/estimates/{id}/bid_form.pdf|.xlsx renders base bid (mid), named alternates[] priced by the same engine (locations-only = whole current scope incl. auto-derived power plant; lines specs = subset, dropping power_plant so O-zone derived lines are not double-carried; kind: deduct signs the credit negative), unit price = wrapped grand total / definition antenna_points (stadium at 1,000 points: $80,528.33 / 1,000 = $80.53 per point), condensed schedule of values in wrap order, exclusions summary from the commercial-draft sheet, and a signature block.

12. Sanity gate math (v0.7.0)

Six rule-driven gates (romtool/sanity.py, thresholds in config/sanity.json, checklists in config/checklists.json) recompute on demand from the stored recap. Severity map: hard = missing scope / crew math (block the approved transition, 409); warning = everything else.

  • Labor share: share = wrapped (task + N01 + N02) hours mid per catalog zone letter prefix ÷ total wrapped hours of all minutes-kind lines, vs a per-archetype window. The estimate-wide derived wrap lines (N03 orientation, N04 cleanup) are minutes-kind lines and participate in the shares — a hand example: E06 x1 + B01 x1 under the default crew gives E 0.93 h + B 3.72 h + N03 3.0 h + N04 0.375 h = 8.025 h → shares 11.59% / 46.36% / 42.06%, of which B's window is 0–12% and N's 0–6%: both flag. On the shipped stadium fixture the E-zone share is 70.41% against a 25–65% window: a warning, not a math error — re-band or verify the takeoff.
  • Crew duration: totals.crew_days must equal ceil(direct wrapped mid h / (crews x crew size x h/day)) and totals.crew_weeks must equal ceil(all wrapped mid h / crew-week capacity); mismatch = hard finding (a doctored or broken-engine recap cannot be approved). Implied average hours/crew-week above 300 = plausibility warning.
  • E-density: share of labor lines on E-grade cards vs threshold (default 50%), strictly above fires. Stadium fixture: 24 E of 26 lines = 92.31% → the assumption register has 24 open rows to walk.
  • Unit-cost outliers: line unit cost (wrapped labor $ mid / qty) vs norm-card unit cost = mid minutes / 60 x (tech rate + (N01 ratio + N02 pct) x foreman rate) = $110.20/task-hour at the default crew. Because every line multiplies task hours by the same factor stack, the ratio equals the line's stacked factor — rope 1.75 x exterior 1.3 x night 1.325 = 3.0144 just past the 3.0 band flags the stadium roof A-rows for verify-the-stack review; K-adder rows skip the access factor (3.0144 vs 1.7225) so they do not self-flag.
  • Missing scope: per archetype, an expected zone entry is satisfied by any labor line whose zone matches the prefix. The shipped stadium fixture reports I (engineering/PM) and J (electrical) missing — hard, and it blocks approval until the rows are added or the estimate drops its archetype.
  • Quote expiry: the governance date math (binding_until inclusive, expired warns once, binding-soon inside the 14-day window) is folded into the report so exports carry one consolidated findings list.

13. Actuals drift math (v0.7.0)

Actuals are stored rows per estimate. For a catalog card with unit card minutes low/mid/high (effective card = labor store + company override layer):

  • row ratio = (actual hours / qty) ÷ (mid minutes / 60);
  • the report ratio is the qty-weighted mean = (sum actual hours) ÷ (sum qty x mid/60) — drift pct = (ratio − 1) x 100 with flags tight ≤ 10%, watch ≤ 25%, else divergent;
  • the proposal median is the qty-weighted median of the row ratios (smallest value whose cumulative qty-weight reaches half the total); hand anchor: E01 = 1.8–3.0 min/ft (mid 2.4, i.e. 0.04 h/ft) with rows 100 ft/4.8 h (1.2×), 50 ft/1.8 h (0.9×), 25 ft/1.2 h (1.2×) → weighted mean 7.8/175/0.04 = 1.1143 (drift 11.43%, watch), weighted median 1.2;
  • guarded refit: proposed low/high = norm low/high x median ratio with the ratio clamped into 0.5–2.0 of the current norm; the 1.2× median proposes 2.16–3.6 min/ft; a 3.0× median clamps to 2.0× (3.6–6.0) and reports clamped; < 2 usable rows proposes nothing;
  • apply is never automatic: apply-refit writes owner-approved low/high to config/company_labor_overrides.json (atomic replace + history entry + audit event). The engine applies the override card in load_labor_catalog() on every later compute, stamps company_override provenance (prior card preserved) on the affected recap lines, and collects company_override_catalog_ids. The measured loop closes: the same actuals read 1.2× against the pre-refit card and 0–10–ish% against the post-refit card (E01 mid 2.88 min/ft after the 2.16–3.6 refit).

14. The stadium package (v0.8.0)

Phase E5 builds the Generic 60k-Seat Stadium as real objects (romtool/stadium_package.py, run via scripts/build_stadium_package.py): an RF project whose cascade solves, a stored labor estimate that scales the fixture-class stadium scenario (rope roof, lift-occupied bowls, scissor concourse, closets, ERCES + neutral-host headend with the O-zone auto-plant, night schedule, dated lockouts, E11/K09/K10/B11 crane/shroud/HVAC rows, L-zone finishing, alternates[] for Add Band 14 FirstNet and Deduct C-band, per-location antenna_points), two bound vendor quotes, and the morning package (dist/stadium-package/: recap exports, bid form, exclusions sheet, assumptions, cashflow, crew plan, bid tab, sanity findings, manifest and MORNING-REPORT.md). GET /reports/stadium serves the manifest.

  • Crew-duration gate basis (E5 correction): the E4 gate recomputed crew_days from all minutes-kind lines, but the engine derives crew_days from LOCATION lines only — the derived estimate-level wrap lines (M05 travel, N03 orientation, N04 cleanup) are sized off crew_days itself, so counting them double-counts. The fixture estimate passed only by a ceil-rounding coincidence; the 60k-seat stadium did not (a false CREW_MATH_INCONSISTENT hard finding). The gate now filters to lines with a location_id, matching the engine; both estimates report consistent crew math.
  • Scaled-stadium hand shape: 260 DAS antenna points (120/80/60), ~28,500 ft of 1/2in heliax, neutral-host + ERCES headend with a 12-hr/30 A plant (strings = ceil(360 Ah / 120 Ah) = 3, N+1 rectifiers = ceil(30/50) + 1 = 2), one crew (5 techs + 1 foreman) over 38 crew-weeks, and the roof rope stack 1.75 × 1.3 × 1.325 = 3.0144 (the intentional outlier the unit-cost gate flags for review). Labor-share bands for the stadium archetype report all zones in-window; E-zone hours sit just inside the 65% window at ~64.7%.
  • Accuracy statement: fixture-class inputs with partial vendor quotes support Class 4 at best (the mid's low/high band sits in AACE Class 5 territory at the bottom).
